One agent.
Every system's language.

Heptapod gives an LLM agent one tool interface to REST, SOAP, and SQL backends, and translates API key, OAuth2, and basic auth underneath. The agent never learns which protocol is behind a tool, so adding a system never changes the agent.

The whole idea in 52 seconds.

The problem, how one call is interpreted for each system, the recorded run, and adding a fourth system. There is no narration; every line you need is on screen.

Agents stall on plumbing, not on the model.

Real organizations run systems built decades apart. Each speaks its own protocol and guards itself with its own auth, and that plumbing usually gets rebuilt from scratch for every client and every system.

Heptapod is the reusable layer underneath: one contract every backend implements, one registry the agent talks to, and one auth layer that turns a declared scheme into request credentials. Adapters never raise; every call returns a structured result the agent can reason about.

One request, three systems, one agent.

A recorded run of the unmodified agent on a free OpenRouter model. Every line below is the real log; the stamps are measured latencies.

Task given to the agent

“Customer Ada Lindqvist called. Find her open support ticket, check inventory stock for the part it references, and update her email in the CRM to ada.l@lindqvist-marine.example.”

  1. Finds the customer in the CRM crm.list_customers ok 21.2ms

    {"operation": "list_customers"}
-> C-1001  Ada Lindqvist  open_ticket_ids: ["T-9001"]

    REST with an API key. The CRM pages its list two at a time; the adapter follows every cursor, so the agent sees all five customers at once.

  2. Reads the ticket ticketing.get_ticket ok 6.4ms

    {"ticket_no": "T-9001", "operation": "get_ticket"}
-> "Bilge pump cycling continuously"  part_ref: BP-310  state: open

    SQL over HTTP with basic auth, bound parameters only. The ticketing system names the customer cust_ref and the part part_ref.

  3. Checks stock for the part inventory.get_stock ok 26.0ms

    {"operation": "get_stock", "partNumber": "BP-310"}
-> RTM-01  bin A-04-2  quantityOnHand: 3

    SOAP with an OAuth2 token the auth layer fetched and cached. Same part, third spelling: partNumber.

  4. Updates her email in the CRM crm.update_customer ok 6.2ms

    {"operation": "update_customer", "email": "ada.l@lindqvist-marine.example", "customer_id": "C-1001"}
-> email: ada.l@lindqvist-marine.example
The agent's answer

Ticket T-9001, “Bilge pump cycling continuously”, references part BP-310. 3 units are on hand at warehouse RTM-01, bin A-04-2. Her email is now ada.l@lindqvist-marine.example.

Failures arrive as data.

Adapters never raise. Bad arguments, HTTP errors, SOAP faults, malformed XML, timeouts, and rate limits all come back as a failed result with a readable reason, which the agent hands to the model so it can correct itself.

Every call is logged once with its system, operation, latency, and outcome, so a failure traces to one adapter without reading the transcript.

Fault inventory.get_part failed 
AdapterResult(
    success=False,
    data=None,
    error="inventory returned HTTP 500: SOAP fault soap:Client: part XX-1 does not exist",
)

A fourth system is one class and one table.

The registry, the auth layer, and the agent never change. The three adapters above are 117, 134, and 129 lines, documentation included.

1

Write the adapter

Declare a name, a schema, and an auth scheme. Return a result; never raise.

class BillingAdapter:
    name = "billing"
    input_schema = {...}

    def __init__(self, base_url):
        self.auth_config = {
            "type": "api_key",
            "header": "X-Billing-Key",
            "secret_ref": "BILLING_API_KEY",
        }

    def execute(self, input, credentials):
        ...  # -> AdapterResult

One table in adapters.toml. Secrets stay in the environment.

Why Heptapod.

Heptapods are the visitors in Arrival, adapted from Ted Chiang's Story of Your Life. Their written language encodes meaning non-linearly, so understanding them is a universal translation problem, not a word-for-word swap.

Getting systems that were never designed to talk to each other to understand one agent is the same kind of problem. The mark is seven display segments closed into one ring, with one lit: the system currently being spoken to.
